# Public operator access and private window activation

This fork keeps CPA Manager Plus's full management interface private and adds a
small public operator interface. Existing CPA credentials and OAuth refresh stay
in CLIProxyAPI; the scheduler never reads or stores OAuth tokens.

## Deployment

Run one Manager per CPA pool. Existing configuration and connection import work
as upstream. Enable operator mode with:

```
HTTP_ADDR=127.0.0.1:18330
CPA_OPERATOR_ADDR=127.0.0.1:18331
CPA_OPERATOR_PASSWORD_FILE=/private/operator-password
```

`CPA_OPERATOR_PASSWORD_FILE` must contain at least 12 characters. Use a generated
password. The public username is `operator` (HTTP Basic over HTTPS). The public
and admin listeners are separate HTTP servers and handler trees. Startup refuses
operator mode unless the admin listener uses a loopback address. Bind the public
listener to loopback as well when using a local reverse proxy.

Forward public `/privat/` (with prefix stripped) to the operator listener and
`/privat/v1/*` to CPA as before. Publish the admin listener only through Tailscale
Serve, without Funnel. **Do not publicly proxy the admin listener.** Tailscale
policy controls network access; the Manager admin key provides the application
login. Forwarded identity/IP headers do not grant either role.

Operator API allowlist:

- `GET /` — operator HTML.
- `GET /api/accounts` — redacted account identity, quota and request counts.
- `POST /api/account/status` — exactly `{id, disabled}`, nothing else.

POST requires same-origin JSON; unknown fields are rejected. Credentials, raw
ID tokens, auth-file paths, client keys, proxy settings and configuration are not
serialized into operator responses. Request counts are CPA's in-memory account
counters; historical analytics remain in the full Manager UI.

## Schedule configuration

On the Tailscale-only admin origin open `/activation/`, or choose **Window
activation** in the Manager navigation. Log in with the Manager admin key.
Configure each Codex account's enable switch, local `HH:MM` times and IANA timezone.
For example, `05:00, 10:00, 15:00, 20:00` in `Europe/Berlin`. Each row shows its next
scheduled time and last outcome. Schedule edits and **Run now** require admin
authentication; the public listener has no routes for them.

Schedules default to empty/disabled. Existing accounts are discovered from CPA,
including accounts added later, without an independent credential registry.
The model is fixed to `gpt-6-luna`, reasoning `low`, and a minimal “OK?” prompt.

One process-local worker checks every 30 seconds. It targets the selected account
using CPA's `auth_index` and `$TOKEN$` API-call substitution; it does not use pooled
round-robin requests or change account prefixes. Before sending it checks the
provider's reported window. Active windows are skipped, imminent resets wait
inside a ten-minute slot tolerance, disabled accounts and exhausted weekly
allowances are skipped. Missing/ambiguous quota data fails closed.

Attempts are persisted atomically **before** the provider call. There is no
retry/failover after an uncertain request, no duplicate delivery after a restart,
and no catch-up burst after downtime. Date/time slot keys avoid repeated sends
when daylight-saving time falls back; nonexistent spring-forward slots are
skipped. The settings/run file is `window-activation.json` under Manager's data
directory, mode 0600, and contains no OAuth tokens. Preserve it with normal Manager
backups. Run only one Manager process per data directory (upstream's process lock
already enforces this).

The result distinguishes a completed request from a verified five-hour reset.
A small request cannot restart an active window; plan/model behavior remains an
upstream policy. Test an expired account before relying on automatic activation.

## Public T3 usage hubs

The operator listener additionally supports only:

- `GET /v0/management/auth-files` with the CPA management key: safe T3 metadata,
  without credentials or configuration.
- `POST /v0/management/api-call` with that key: only GET reads of the exact Codex
  quota and reset-credit-list URLs. Caller headers are ignored and generated by
  the server. Arbitrary URLs, credential changes, inference and reset-credit
  redemption are forbidden on this public endpoint.

Route these two paths to the correct operator listener, selecting each pool by
its management key. The inference client key does not authorize hub access; the
operator password does not authorize private management. T3 hub URLs and existing
management keys remain usable. T3's public **Use reset** mutation is intentionally
blocked: perform privileged actions from private administration.

## Validation

```
cd apps/manager-server
go test ./...
go test -race ./internal/operator
```

Tests cover the DTO boundary, public/private role separation, unknown-field and
CSRF rejection, account-targeted inference, low-cost model settings, active-window
skips, persisted attempts/restarts, timezone slot selection and missed-run behavior.
The upstream frontend also builds with `npm run build`.
